# Bubble Royale Server

C++ / IOCP 기반 실시간 멀티플레이 게임 서버.
크레이지아케이드의 조작감을 **24인 라운드제 배틀로얄**로 옮겼다.

> **넥슨 넥토리얼 게임 프로그래머 지원용 포트폴리오입니다.**
> 2026.08.27 ~ 09.05, 10일간 혼자 만들었습니다.
> 작성자는 C++ 서버가 처음이며, 이 저장소의 목표는 코드를 완성하는 것이 아니라
> **모든 선택을 직접 설명할 수 있게 되는 것**입니다.
> 그 과정을 [`devlog/`](devlog/)에 매일 세 줄로 남깁니다.

## 무엇을 만드는가

45×39 격자 맵(15×13 조각 3×3) 위에서 **24명**이 물풍선을 놓고 싸운다.
시간이 지나면 바깥 구역부터 물이 차올라 중앙으로 몰리고, 최후 1인이 이긴다.

**서버 권위(server-authoritative)** 구조다. 클라이언트는 입력만 보내고
이동 유효성 · 폭발 판정 · 피격 · 침수는 전부 서버가 결정한다.
서버와 클라이언트가 같은 판정을 내야 하므로 **float를 쓰지 않고 고정소수점 정수 연산만** 쓴다.

핵심 조작은 크레이지아케이드의 **걸치기**다. 타일 경계에 걸쳐 서면
판정이 먼저 있던 쪽으로 남아 물줄기를 피할 수 있다.
그래서 위치는 연속값(타일당 256 단위)으로, 판정은 타일 단위로 분리했다.
연속 좌표를 매 틱 보내야 하므로 **AOI(관심 영역) 브로드캐스트 최적화가 필수**가 된다.
그것이 이 프로젝트의 핵심이고, 전원 브로드캐스트와 AOI 적용의 전후 수치를 측정해 비교한다.

구성: **웹 Canvas 클라이언트 ← Node WebSocket 브리지 ← C++ 서버.**
부하·지연 측정용 C++ 더미 클라이언트는 브리지를 우회해 서버에 직접 붙는다.

게임 규칙, 프로토콜, 상수, 측정 계획, 일별 완료 조건은 [`SPEC.md`](SPEC.md)에 있다.

## 빌드 & 실행

**환경:** Windows 11 / Visual Studio 2022 (v143) / C++17 / x64 / WinSock2

```
BubbleRoyale.sln 을 열고 Debug|x64 로 빌드
```

또는 명령줄에서:

```bat
msbuild BubbleRoyale.sln -p:Configuration=Debug -p:Platform=x64
```

산출물은 `bin\x64\Debug\` 에 나온다. **서버를 먼저 켜고** 클라이언트를 켠다.

```
bin\x64\Debug\Server.exe
bin\x64\Debug\Client.exe
```

클라이언트를 여러 개 띄우면 한 명이 친 것이 전원에게 전파된다.

```
[Server] 4 workers started
[Server] listening on port 9000
[Session] 127.0.0.1:51234 connected
[Session] 127.0.0.1:51234 packet id=1 size=9
[Session] 127.0.0.1:51234 disconnected
[Session] 127.0.0.1:51234 closing
[Session] 127.0.0.1:51234 fully closed
```

로그 접두어는 두 가지다. 주소가 붙으면 `[Session]`, 서버 전체 얘기면 `[Server]`.

### 검증 도구

`tools/` 의 두 프로그램으로 확인한다. `practice/build.bat` 으로 빌드한다.

```bat
cd practice
build.bat ..\tools\probe.cpp
build.bat ..\tools\bot.cpp
```

| 도구 | 무엇을 확인하나 |
|---|---|
| `probe.exe` | 패킷 경계. 1바이트씩 쪼개 보내기 / 몰아 보내기 / 둘이 섞인 경우 / 브로드캐스트 |
| `bot.exe [봇수] [초]` | 부하와 레이스. 봇이 동시에 붙었다 끊기를 반복한다 |

`bot.exe` 를 돌린 뒤 서버 로그에서 `connected` 수와 `fully closed` 수가 같아야 한다.
다르면 세션이 샌 것이다.

최근 확인: 봇 24개 12초에 접속 2855, 서버 `fully closed` 2855, 누수 0.

## AI를 어떻게 썼는가

이 프로젝트는 AI 어시스턴트를 적극적으로 썼고, **어디까지 쓸지를 문서로 못 박았다.**
[`CLAUDE.md`](CLAUDE.md)가 그 규칙이다. 코드를 세 구역으로 나눈다.

| 구역 | 범위 | AI 사용 |
|---|---|---|
| **A** | IOCP 코어, 세션 생명주기, 링버퍼·패킷, 락 설계, 게임 판정, AOI | **4단계 학습 루프**를 끝까지 돌린다 — 보여주기 → 이해 점검 → **파일 비우고 다시 쓰기** → 구술 테스트 |
| **B** | WinSock API 시그니처, 에러 코드, C++ 문법 | 설명과 짧은 예시까지만 |
| **C** | 빌드 설정, 부하 테스트 도구, 측정 스크립트, 문서 | 전부 위임 — 여기서 아낀 시간을 A에 쓴다 |

A구역 규칙은 **8/27 당일에 한 번 개정했다**(커밋 `621adf8`).
처음 규칙은 "완성 코드를 절대 주지 않는다"였는데, C++ 입문 단계에서는
학습이 아니라 정지가 되어서 4단계 루프로 바꿨다. 기준을 낮춘 것이 아니라
**보고 한 번 치는 것에서, 지우고 다시 쓴 뒤 구술 테스트까지 통과하는 것으로 올렸다.**

`practice/` 폴더가 그 3단계(지우고 다시 쓰기)의 기록이다.
