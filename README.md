# Bubble Royale Server

C++ / IOCP 기반 실시간 멀티플레이 게임 서버.
크레이지아케이드의 조작감을 **24인 라운드제 배틀로얄**로 옮겼다.

> **넥슨 넥토리얼 게임 프로그래머 지원용 포트폴리오입니다.**
> 2026.08.27 ~ 09.05, 10일간 혼자 만들었습니다.
> 작성자는 C++ 서버가 처음이며, 이 저장소의 목표는 코드를 완성하는 것이 아니라
> **모든 선택을 직접 설명할 수 있게 되는 것**입니다.
> 그 과정을 [`devlog/`](devlog/)에 매일 세 줄로 남깁니다.

**바로 해보려면** — Windows 에 Node 가 있으면 이거 하나면 된다.
빌드하고, 서버와 다리를 띄우고, 브라우저를 연다. 빈자리는 봇이 채우므로 혼자서도 판이 돈다.

## 무엇을 만드는가

45×39 격자 맵(15×13 조각 3×3) 위에서 **24명**이 물풍선을 놓고 싸운다.
시간이 지나면 바깥 구역부터 물이 차올라 중앙으로 몰리고, 최후 1인이 이긴다.

**서버 권위(server-authoritative)** 구조다. 클라이언트는 입력만 보내고
이동 유효성 · 폭발 판정 · 피격 · 침수는 전부 서버가 결정한다.
서버와 클라이언트가 같은 판정을 내야 하므로 **float를 쓰지 않고 고정소수점 정수 연산만** 쓴다.

핵심 조작은 크레이지아케이드의 **걸치기**다. 타일 경계에 걸쳐 서면
판정이 먼저 있던 쪽으로 남아 물줄기를 피할 수 있다.
그래서 위치는 연속값(타일당 256 단위)으로, 판정은 타일 단위로 분리했다.
연속 좌표를 매 틱 보내야 하므로 **AOI(관심 영역) 브로드캐스트 최적화가 필수**가 된다.
그것이 이 프로젝트의 핵심이고, 전원 브로드캐스트와 AOI 적용의 전후 수치를 측정해 비교한다.

구성: **웹 Canvas 클라이언트 ← Node WebSocket 브리지 ← C++ 서버.**
공개 게임은 9000번 서버를 쓰고, 코드 방은 브리지가 9100~9199번에 별도 서버를 띄운다.
그래서 방끼리 맵·라운드·참가자가 섞이지 않는다.
부하·지연 측정용 C++ 더미 클라이언트는 브리지를 우회해 서버에 직접 붙는다.

게임 규칙, 프로토콜, 상수, 측정 계획, 일별 완료 조건은 [`SPEC.md`](SPEC.md)에 있다.

## 빌드 & 실행

**환경:** Windows 11 / Visual Studio 2022 (v143) / C++17 / x64 / WinSock2

처음 받았으면 이거 하나면 된다.

```bat
run.bat
```

필요하면 빌드하고, 서버와 다리를 띄우고, 브라우저를 연다.
콘솔 창 두 개가 뜨고 그게 서버 로그다. 아무 키나 누르면 둘 다 내려간다.
빈자리는 봇이 채우므로 **혼자서도 판이 돈다.**

인자는 그대로 서버에 넘어간다.

| | |
|---|---|
| `run.bat fast` | 6분짜리 침수 일정이 36초로 줄어든다. 손맛 볼 때 |
| `run.bat seed 42` | 매번 같은 판. 이상한 걸 봤을 때 그 판을 다시 부른다 |
| `run.bat bots 8` | 빈자리를 봇 8명까지 채운다 (`bots 0` 이면 안 채운다) |
| `run.bat aoi 0` | AOI 를 끈다. 켜고 끈 값을 비교할 때 |

지연이 있는 네트워크를 흉내 내려면 다리에 스위치가 있다.
같은 컴퓨터에서만 돌려보면 손맛을 지연 0 을 전제로 맞추게 된다.

```bat
node web\bridge.js delay 80 jitter 30
```

**내 캐릭터는 화면이 미리 움직인다** (`web/predict.js`).
서버 권위는 그대로고, 화면이 서버와 같은 계산을 미리 한 번 돌려 그려준다.
서버 답이 오면 맞춰보고 어긋난 만큼만 조용히 녹인다.

```
키를 누르고 화면이 움직이기까지
  지연 0        32ms -> 17ms
  왕복 160ms   217ms -> 17ms      예측이 아예 틀려 순간이동한 횟수 0
```

**같은 씨앗이면 같은 판이라는 것을 지문으로 확인한다.**
씨앗만 찍으면 씨앗을 넣었다는 것까지만 증명된다.

```
[Server] map 45x39 generated (seed 777, 27 spawns, fingerprint 18178FBC)
[Server] map 45x39 generated (seed 777, 27 spawns, fingerprint 18178FBC)
[Server] map 45x39 generated (seed 778, 27 spawns, fingerprint F315DC7E)
```

### 손으로 띄우기

```
BubbleRoyale.sln 을 열고 Debug|x64 로 빌드
```

또는 명령줄에서:

```bat
msbuild BubbleRoyale.sln -p:Configuration=Debug -p:Platform=x64
```

산출물은 `bin\x64\Debug\` 에 나온다. **서버를 먼저 켜고** 클라이언트를 켠다.

```
bin\x64\Debug\Server.exe
bin\x64\Debug\Client.exe
```

클라이언트를 여러 개 띄우면 한 명이 친 것이 전원에게 전파된다.

```
[Server] 4 workers started
[Server] listening on port 9000
[Session] 127.0.0.1:51234 connected
[Session] 127.0.0.1:51234 packet id=1 size=9
[Session] 127.0.0.1:51234 disconnected
[Session] 127.0.0.1:51234 closing
[Session] 127.0.0.1:51234 fully closed
```

로그 접두어는 두 가지다. 주소가 붙으면 `[Session]`, 서버 전체 얘기면 `[Server]`.

### 웹으로 보기

브라우저는 TCP 를 못 쓴다. 그래서 WebSocket 을 TCP 로 바꿔주는 다리를 하나 둔다.

```
브라우저 Canvas  --WebSocket-->  web/bridge.js  --TCP-->  Server.exe
```

```bat
bin\x64\Debug\Server.exe fast
node web\bridge.js
```

그다음 `http://127.0.0.1:8080` 을 연다. 창을 여러 개 열면 여러 명이 된다.
`fast` 를 붙이면 6분짜리 침수 일정이 36초로 줄어든다. 손맛을 볼 때 쓴다.

로비에서 들어가는 방법은 두 가지다.

- **공개 게임 참가**: 9000번의 공개 게임으로 바로 들어간다. 기본 설정은 봇이 12자리까지 채운다.
- **코드 방**: 봇 수를 고르고 `방 만들기`를 누른다. 화면 위에 뜬 6자리 코드를 같은 PC의 다른 브라우저 창에서 `받은 방 코드`에 입력한다. `봇 없음`은 두 번째 사람이 올 때까지 기다리고, 봇을 고르면 바로 시작한다. 진행 중 들어온 사람은 그 판을 관전하고 다음 판부터 참가한다.

코드 방은 실제로 분리된 C++ 서버다. 동시에 8개까지 만들 수 있고, 아무도 없는 방은
10분 뒤 닫힌다. 로컬 시연용이므로 브리지와 모든 방 서버는 `127.0.0.1`에만 열린다.
다른 PC의 친구가 접속하는 온라인 방은 아니다. 그 기능에는 별도 배포와 방화벽·인증 설계가 필요하다.

**`npm install` 이 필요 없다.** 다리는 Node 기본 모듈만 쓴다.
WebSocket 악수와 프레임을 `bridge.js` 안에 직접 구현해 뒀다.

**클라이언트는 게임 상수를 하나도 갖고 있지 않다.**
타일 크기, 틱레이트, 퓨즈 시간, 걸치기 임계값을 전부 접속할 때 서버가 보내준다.
같은 숫자를 `.js` 에 또 적으면 한쪽만 고쳤을 때 서버와 화면이 갈리기 때문이다.

## 저장소 구조

```
BubbleRoyale.sln
├─ Common/            서버와 클라이언트가 같이 보는 것
│   ├─ Protocol.h        패킷 헤더 · 포트 · 패킷 종류
│   └─ GameConstants.h   게임 규칙 상수. 값은 여기 하나만 있다
├─ Server/src/
│   ├─ main.cpp          패킷 처리 + 워커 루프 + 스냅샷 + 시작/종료
│   ├─ Session.h         Session / IoContext / 참조 카운트
│   ├─ SessionManager.h  세션 목록 + 자물쇠 + CloseSession
│   ├─ Network.h         PostRecv / StartSend / SendPacket / Broadcast
│   ├─ RecvBuffer.h      받은 바이트를 쌓아두는 버퍼 (커서 두 개)
│   ├─ SendBuffer.h      보낼 것을 쌓아두는 링버퍼
│   ├─ JobQueue.h        워커가 꽂고 틱 스레드가 가져가는 주문 꽂이
│   ├─ GameMap.h         45x39 판. 조각 아홉 개를 뽑아 붙이고 뒷정리
│   ├─ Movement.h        한 축 이동 · 걸치기 판정 · 코너 보정
│   ├─ Game.h            자료구조 전부 + 사람 입장/퇴장/입력/이동
│   ├─ Bubble.h          물풍선 · 폭발 · 연쇄 · 아이템 · 피격
│   ├─ Flood.h           침수
│   ├─ Bot.h             봇 두뇌. roundsim 과 서버가 같이 쓴다
│   ├─ Aoi.h             누구에게 무엇을 보낼 것인가 + 송신량 계측
│   ├─ SectorTemplates.h 손으로 그린 맵 조각 3종 (마을·사막·얼음골)
│   ├─ GameTick.h        한 틱에 무엇을 어떤 순서로 하는가
```

## AI를 어떻게 썼는가

이 프로젝트는 AI 어시스턴트를 적극적으로 썼고, **어디까지 쓸지를 문서로 못 박았다.**
[`CLAUDE.md`](CLAUDE.md)가 그 규칙이다. 코드를 세 구역으로 나눈다.

| 구역 | 범위 | AI 사용 |
|---|---|---|
| **A** | IOCP 코어, 세션 생명주기, 링버퍼·패킷, 락 설계, 게임 판정, AOI | **4단계 학습 루프**를 끝까지 돌린다 — 보여주기 → 이해 점검 → **파일 비우고 다시 쓰기** → 구술 테스트 |
| **B** | WinSock API 시그니처, 에러 코드, C++ 문법 | 설명과 짧은 예시까지만 |
| **C** | 빌드 설정, 부하 테스트 도구, 측정 스크립트, 문서 | 전부 위임 — 여기서 아낀 시간을 A에 쓴다 |

A구역 규칙은 **8/27 당일에 한 번 개정했다**(커밋 `621adf8`).
처음 규칙은 "완성 코드를 절대 주지 않는다"였는데, C++ 입문 단계에서는
학습이 아니라 정지가 되어서 4단계 루프로 바꿨다. 기준을 낮춘 것이 아니라
**보고 한 번 치는 것에서, 지우고 다시 쓴 뒤 구술 테스트까지 통과하는 것으로 올렸다.**

`practice/` 폴더가 그 3단계(지우고 다시 쓰기)의 기록이다.
