# 2026-08-27 (D-11) — 세팅과 blocking 에코

**1. 오늘 하려던 것**

VS2022 x64 프로젝트 두 개(Server / Client)를 만들고, `.gitignore`를 먼저 커밋한 다음
코드를 커밋. 
blocking TCP 에코 서버와 클라이언트 동작시키기.

전부 완료했다. 클라이언트 역할의 터미널에서 입력한대로 돌아오는것을 확인했다 

**2. AI에게 물은 것 / 어떻게 물었나**

빌드 설정과 `.gitignore`는 통째로 맡겼고, 에코 서버는 개념·API·경계 조건만 받고 내가 썼다. 

막힐 때는 "고친 코드 주지 말고 어디가 왜 틀렸는지
말로만 지적해줘"로 물었다.

중간부터 설명이 귀에 잘 안들어오길래 비유해가면서 쉽게 설명 해달라고 요구했다.
그 뒤로 소켓을 전화기 비유로 설명 받았다. `listen` 소켓은 가게 대표번호,
`accept`가 돌려주는 건 그 손님 전용 전화기. 이걸로 붙었다.

**3. AI가 틀린 것 / 내가 어떻게 잡았나**

- 완성 코드를 안주고 설명만 들으며 코드를 처음부터 써나간다는 규칙 자체가 나에게는 어려웠다. 
  반나절 해보고 4단계 학습 루프(보여주기 → 이해 점검 → 연습용 파일에 안보고 처음부터 쓰기 → 구술 테스트)로 갈아엎었다.
  바꾼 뒤에는 쉬워진게 맞다.
  전체 구조랑 순서, 형태는 설명으로 이해했는데 막상 치려면 함수랑 상수 이름 하나하나를 알아야 했다.
  모르는 단어를 빈 화면에서 만들어낼 수는 없다. 그건 써가면서 익히는 거다.
  대신 앞을 풀어준 만큼 뒤에 관문을 붙였다.
  전에는 한 번 쳐서 돌아가면 끝이었다.
  지금은 안 보고 다시 쓰고 코드 없이 구술 테스트까지 통과해야 넘어간다.
- AI가 빌드 경로를 잘못 짚어 옛날 exe를 돌리고 "아직 실패한다"고 보고했다.
  솔루션으로 다시 빌드하니 이미 고쳐져 있었다.
    결과가 안 바뀌면 코드보다 내가 지금 보는 게 방금 빌드한 물건이 맞는지부터 의심해야 한다.
- `inet_pton` 설명이 두루뭉술해서 반환값 대신 결과 구조체를 검사했다.
  `127.0.0.1`은 숫자로 16,777,343이라 무조건 실패로 튕겼고 `connect`까지 가보지도 못했다.

**내가 만든 버그**

서버 반복문을 클라이언트에서 복사해왔더니 `strlen`으로 길이를 재는 부분이
`recv`보다 위에 있었다.
아직 받지도 않은 데이터의 길이를 미리 잰 셈이다.
게다가 그 상자는 초기화도 안 해서 안에 뭐가 들었는지 모르는 상태였다.
운 나쁘면 5바이트 받아놓고 수백 바이트를 긁어서 보내고,
길이가 0으로 나오면 받은걸 버리고 서로 계속 기다린다.
/W4로 켜놨는데 컴파일러는 경고를 하나도 안 냈다.

왜 이렇게 썼냐면 클라이언트에서는 그게 맞는 코드였기 때문이다.
키보드 입력은 끝 표시가 있으니 직접 세는게 맞다.
그런데 네트워크로 온 바이트에는 끝 표시가 없다. `recv`가 몇 바이트인지 알려준다.
맞는 코드를 맞지 않는 자리에 옮긴 것이다.
복사가 문제가 아니라 이 코드가 왜 여기 있는지 안 보고 옮긴게 문제였다.

**확인해둔 것**

클라이언트를 두 개 붙여봤다. 두 번째는 `connected`까지만 뜨고 답이 안 온다.
blocking이라 서버가 첫 손님을 붙잡고 서 있기 때문. 첫 번째가 끊어야 처리된다.
이게 내일 IOCP가 필요한 이유다.
