# 2026-08-31 (D-6) — 틱 스레드와 주문 꽂이

**1. 오늘 하려던 것**

워커 넷이 각자 패킷을 처리하던 것을 틱 스레드 하나로 몰아주는 것.

에코일 때는 문제가 없었다. 게임판이 생기면 다르다.
물풍선이 터지면 블록과 캐릭터를 같이 건드리는데, 그걸 워커 넷이 동시에 하면
자물쇠가 몇 개 필요한지 아무도 못 답하게 된다.
그래서 게임 처리는 한 명한테 다 준다. 주인이 하나면 자물쇠가 없다.

워커는 패킷을 잘라서 꽂이에 꽂고 바로 다음 손님에게 간다.
틱 스레드가 30Hz로 꽂이를 통째로 가져가서 처리한다.

완료 조건은 패킷이 워커에서 틱 스레드로 넘어가 처리되는 것이었다.

```
접속 2560   entered 2560   left 2560   fully closed 2560
probe 10 PASS / 0 FAIL      봇 에러 0
job queue full 0            tick behind 0
```

12초에 패킷 7742개가 워커에서 틱 스레드로 건너갔고 틱은 한 번도 안 밀렸다.
네 숫자가 같다는 게 꽂이를 거쳐도 새는 세션이 없다는 뜻이다.

로그 순서도 확인했다. `closing` 다음에 `left`가 나오고 그다음이 `fully closed`다.
꽂이에 꽂힌 주문이 참조를 하나 들고 있어서 그동안 세션이 안 지워진 것이다.

어제 못 맞힌 구술도 다시 했다. 소유 스레드 문제다.
`g_sessions`에 락이 필요 없다고 답해서 틀렸는데, 장면을 하나 받고 나서 스스로 고쳤다.
어제는 세 번 밀어야 나왔고 오늘은 한 번 밀어서 나왔다.

**3. AI가 틀린 것 / 내가 어떻게 잡았나**

- 틱 루프 타이밍 주석이 틀렸다.

  AI가 `// 더하기만 하면 처리 시간이 조금씩 쌓여서 점점 느려진다` 라고 써줬다.
  직전 target에서 33을 더하면 처리 시간은 안 쌓인다. 저건 지금 시각에서 더할 때만 맞는 말이다.

  진짜 이유는 33이 정확한 값이 아니라는 것이다. 1000/30은 33.333이다.
  33씩 더하면 한 틱마다 0.333ms씩 빨라져서 1분이면 0.6초, 5분 한 판이면 3초가 어긋난다.
  `GameConstants.h`에 시간을 전부 틱으로 적어놨으니 그게 그대로 게임 시각이 된다.

  이건 내가 구술 4번을 못 맞혀서 드러났다. 답을 확인하다 AI가 자기 주석이 틀렸다고 했다.

  > (여기는 내가 다시 쓴다)

- AI가 `ProcessPackets`의 `if (s->closing == 1) return;` 을 지우라고 했다.
  안 지우고 뒀는데 그게 맞았다. 이제 틱 스레드도 `CloseSession`을 부를 수 있어서
  있는 쪽이 맞다. AI도 나중에 그대로 두라고 말을 바꿨다.

- AI가 어제와 똑같이 문자열 이스케이프를 또 깨먹었다.
  파일에 `%ld\n` 을 넣으려다 `\n` 이 진짜 줄바꿈으로 들어갔다.
  어제 같은 걸로 네 번 넘어졌는데 오늘 또 했다.
